Headline — three stacked problems, in rough contribution order
(1) Trinity's custom scorecard overlaps — seven of the twenty questions score the same "did they talk about features / amenities" behavior, stacking penalties 7:1 on a single missed sales behavior. (2) Two Entrata-side scoring bugs — a conditional ID-verification question that isn't properly N/A'd (293 calls), and a scoring-pipeline bug where real leasing calls occasionally get all 20 questions marked N/A and are then scored 0 (119 calls). (3) Real agent gaps — Trinity's agents consistently miss four lead fundamentals (asking how caller heard, why they're moving, capturing email, specific appointment attempts).

Short answer: is it the model, the agents, or the rubric?

All three, but not equally. Roughly 55% of the score drag comes from how Trinity's custom scorecard was designed. ~20% comes from Entrata-side scoring bugs that we need to fix. ~25% comes from genuine, coachable agent behavior gaps. Model reading accuracy is high — in a 25-call transcript audit, the model got nearly every question correct where it had a clear signal to work with. Where it fails, it fails on compound-requirement edge cases and conditional-question handling, not on reading comprehension.

Rubric design — the biggest driver

Trinity authored this 20-question rubric themselves. The design decisions below are Trinity's, not Entrata defaults. That means the fix is a customer-education + co-design conversation rather than a product bug.

Overlap #1 — "Did the agent mention features / amenities?" counted 7 times

Seven of twenty questions all score some variant of "mentioned apartment / community features or benefits." An agent who skips amenity-talk loses up to 7 of 20 points on a single behavioral miss — a 35-point penalty on a 100-point scale.

Weighting is flat — all 20 questions worth equal points

The scoring formula is Yes / (Yes + No) × 100, confirmed to within rounding error on 6,168 of 6,174 rows. Every question is weighted equally — "used polite language" counts the same as "set a specific appointment." Combined with the overlap above, "talking about amenities" ends up worth 35 points but "setting a tour" is worth 5. That's inverted from what any leasing GM would want.

Scoring pipeline bugs — Entrata-side

These are not model competence issues. These are specific defects in how questions are being evaluated. Both validated with transcript-level evidence.

Bug #1 — Conditional ID question not being N/A'd
Severity: Medium · 293 calls affected (4.7%)
Confirmed 5/5

Q03 reads: "If an in-person appointment or tour was scheduled, did the team member inform the caller that a valid ID will be required?" It is explicitly conditional. If no appointment was scheduled, the correct answer is N/A — not No.

We validated 5 calls in this cohort. In every one, no appointment was scheduled — model correctly marked "appointment=No" but incorrectly marked "ID=No" instead of "ID=N/A". The model knows how to use N/A (it applies it 16.6% of the time on the "why moving" question). It's just not being told to apply it here.

Bug #2 — 119 real leasing calls scored as 0
Severity: High · 119 calls (1.9%)
Validated — new finding

119 calls have all 20 questions marked N/A. The scoring formula interprets 0/0 as 0, so these calls are scored as perfect failures. Original hypothesis: these are hang-ups and wrong numbers that should be excluded from scoring. Reality from transcript audit: that is not what's happening.

We validated 3 calls in this cohort. All 3 were legitimate leasing conversations:

  • • 279783518 — 87s inquiry call, agent opened properly, gave pricing, explained cosigner program. Should have scored ~25–35.
  • • 276071182 — 293s full leasing call. Agent captured name, timeframe, source attribution, move reason, discussed features/laundry, mentioned ID requirement, mentioned 1-month free promo. Should have scored 70–85. Agent was told she got a 0.
  • • 275972668 — 128s pre-leasing inquiry for next school year, agent explained no pricing yet, captured phone. Should have scored ~30–45.

This is a severe issue at the agent level. A single mystery zero kills an agent's weekly average. The scoring pipeline needs to either: (a) correctly answer the questions on these calls, or (b) exclude the call from the agent's score entirely rather than scoring it 0.

Takeaway on model accuracy

The model's base reading comprehension is strong. Where it fails, it tends to fail on paraphrased or non-canonical phrasings ("come in" vs "schedule a tour", "bring an ID" vs "valid ID required"). These are prompt-engineering fixes, not model-replacement fixes. We should audit the per-question prompt definitions and add synonym coverage.

Where Trinity's agents genuinely have gaps

Stripping out the structural issues, these are areas where even deduplicated, well-weighted scoring would still mark the agents down. These are coachable, and most of them are leasing fundamentals.

Top coaching opportunities
1. Confirm how caller heard (76% No)
Marketing attribution is being skipped. One sentence: "How did you hear about us?"
2. Ask why they're moving (64% No)
Discovery question that drives tour conversion. Agents are skipping it entirely.
3. Set a specific appointment (59% No)
Only 39% of calls end with an actual appointment attempt. This is the single biggest revenue lever.
4. Capture email AND phone (58% No)
Phone is auto-captured (inbound), but agents routinely don't ask for email. Both are required for most CRMs.
5. Use caller's name (55% No)
Agents are capturing names but not using them back in conversation. Simple rapport builder.
6. Discuss the neighborhood (82% No)
Confirmed by transcript audit — agents rarely mention nearby amenities, schools, highways, dining. "Location, location, location" is a leasing fundamental being systematically missed.

Transcript validation methodology

To separate model errors from rubric design issues from real agent gaps, we spot-checked 25 calls across 5 stratified groups. Caller PII has been redacted from this document; call IDs and property/agent context retained for internal reference.

Findings log
▸ ID-trap bug: 5/5 confirmed

In all 5 sampled calls, no appointment was concretely scheduled, yet the ID question was marked "No" instead of "N/A". Confirmed across the full score range: calls scoring 5, 5, 26, 89, and 90 all showed the same pattern.

One case (call 275319166, score 89) is particularly instructive: the caller chose "send me the application" instead of a tour; the agent respected that preference; the rubric then penalized the agent on the ID question anyway.

▸ Neighborhood question: 7/8 model-accurate

Across 8 mid-high score calls where the neighborhood question was marked "No", the model was correct 7 times. Agents genuinely don't describe the surrounding area, nearby amenities, or location benefits. The 81.8% No rate on this question — the worst in the whole dataset — is a real agent gap, not a model problem.

The one edge case (call 274440622) involved an agent giving detailed highway exit directions ("down 75... Exit 242... North or south") which could arguably count as area info depending on how the question is interpreted.

▸ Compound opening question: 2/3 model-accurate

Two of three sampled high-score calls genuinely missed the "thank you for calling" portion of the opening (agents used a terse "[Property]. [Name] speaking." format). The third was a model false negative — agent did all three correctly but got dinged, likely due to transcription punctuation.

Noteworthy pattern: Many Trinity agents use a terse opening without "thank you." This is a coachable, specific behavior.

▸ Compound email+phone question: 3/3 model-accurate

All three high-scoring calls (all 95s) legitimately failed to capture both email AND phone. Even the top-performing agents are skipping the email ask. This is a specific, measurable coaching opportunity.

▸ Perfect-score sanity check: 3/3 legitimately great calls

All three 100-score calls showed excellent agent performance: proper openings, discovery, amenity + neighborhood pitching, name/phone/email capture, specific appointment attempts, and explicit ID mentions. The model's high end is calibrated — when it says 100, it means it.

▸ Zero-score sanity check: 3/3 are false zeros, not hang-ups Severity-1

Initial hypothesis: these are hang-ups and wrong numbers that should be excluded. Reality: all three sampled calls were legitimate leasing conversations. One (call 276071182) was a strong 5-minute call where the agent captured name, source, move reason, features, pricing, and promo — would score 70+ on a correct evaluation. Agent was told she got a 0.

Extrapolating from the 3-call sample, the 119 all-N/A calls likely include a mix of truly non-scoreable calls and legitimate leasing calls incorrectly scored. The scoring pipeline needs to either correctly evaluate these calls or exclude them, not silently zero them out.

Recommendations

What to tell Trinity, what to fix on our side, and what to validate next.

Message to Trinity — one paragraph
"Thanks for flagging the scores — we did a full-pass analysis on the 6,174 calls from Aug–Sep. The model is generally reading your calls accurately on the behaviors it's asked to detect, so the drag on your averages is coming from two places. First, the custom scorecard your team built scores the same 'mentioned features/amenities' behavior across seven of its twenty questions — any call where the agent skips the amenity pitch loses up to 35 points on what's really one missed behavior. We can walk you through how to deduplicate those or reweight the scorecard. Second — and this one is on us — we found that the conditional ID-verification question ('if a tour was scheduled, did they mention valid ID…') is being marked No on ~300 calls where no tour was even scheduled; it should be N/A. We're fixing that now. We also found 119 calls that got all 20 questions N/A'd and then scored 0 — some were truly non-leasing calls, but at least a few were real leasing calls that your agents handled well; we need to fix that pipeline too. On the agent-coaching side, the signal that's most actionable regardless of rubric changes is: asking how callers heard about you, asking why they're moving, capturing email addresses, and attempting specific appointments — those are the real gaps."
Internal — scoring pipeline fixes Our bug
1. Fix the ID-verification N/A logic
Add explicit prompt rule: if "appointment set" = No, auto-set Q03 to N/A. Prevents 293 unfair penalties/month on this customer alone.
2. Investigate the all-N/A → 0 bug Sev-1
119 calls (1.9%) are getting zeros when at least some are legitimate scoreable calls. Determine root cause (prompt failure? call-type classifier?) and either fix the evaluation or exclude the call from the agent's score.
3. Audit per-question prompt synonyms
Model is missing paraphrased phrasings like "come in" (= set an appointment) and "bring an ID" (= valid ID required). Expand prompt coverage.
4. Surface per-question rationale in UI
If the model emits evidence/quotes per question, show them in Trinity's dashboard. Customers accept low scores when they can see WHY.
Co-design with Trinity — rubric changes Their rubric
1. Deduplicate feature questions
Collapse Q01, Q02, Q08, Q17 → one "value-build" question. Collapse Q05, Q07, Q10 → one "preference-discovery" question. Immediate mean score lift of ~6 points.
2. Weight the rubric
Give tour-set and lead-capture questions 2–3x weight. Give politeness and closing 0.5x weight. Reflects what actually drives Trinity's revenue.
3. Loosen compound requirements
Q14 (name AND use), Q15 (email AND phone), Q18 (thank AND property AND intro) all require multiple conditions. Consider partial credit or splitting into separate questions.
4. Agent coaching focus
Hand Trinity a prioritized coaching list: source attribution, move motivation, email capture, specific appointment attempts, neighborhood pitching. These are rubric-independent wins.
Three questions to confirm with Trinity before next steps
  1. Is this scorecard a Trinity-wide standard, or specific to one property manager?
  2. Are they comparing these scores to a benchmark number we gave them, or just reacting to the absolute values?
  3. Do their internal QA leads agree with the model's grades when they sample calls themselves?

Those three answers determine whether the next move is a product fix, a rubric reset, or a customer-education conversation.
